# Contribution Guidelines

## Branch policy
The repository owner has requested initial structure and documentation work directly on `main`. Once implementation begins, use focused feature branches and pull requests unless the team explicitly agrees otherwise.

## Before coding
1. Read the relevant architecture and API documents.
2. Confirm ownership and acceptance criteria.
3. Agree on shared contract changes before implementation.
4. Never commit secrets or generated build artifacts.

## Pull request expectations
- Describe scope and rationale.
- Link related issue/task where available.
- Include tests and verification evidence.
- Identify contract or migration changes.
- Do not claim tests passed unless they were run.
